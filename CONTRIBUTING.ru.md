## 🚀 Начало работы

```bash
# 1. Форк и клонирование
# Нажмите кнопку "Fork" на GitHub.com, затем откройте терминал:
git clone https://github.com/<ВАШ_НИКНЕЙМ>/Privilege-Auction-OPD.git
cd Privilege-Auction-OPD

# 2. Добавьте upstream для синхронизации с основным репозиторием
git remote add upstream https://github.com/IceMan4ik/Privilege-Auction-OPD.git

# 3. Настройка окружения
# Следуйте инструкциям в основном README.md 
# (установка зависимостей, сборка проекта и т.д. в зависимости от выбранного стека)
```

## 🌳 Работа с ветками (Branching)

Всегда создавайте новые ветки от ветки `dev`:

```bash
git checkout dev
git pull upstream dev
git checkout -b feature/название-вашей-задачи
```

**Правила именования:**
- `feature/краткое-описание` — для новых функций
- `fix/краткое-описание` — для исправления ошибок
- `docs/краткое-описание` — для обновления документации

**Правило:** Одна ветка = одна конкретная задача.

## 📝 Коммиты

Мы придерживаемся стандарта [Conventional Commits](https://www.conventionalcommits.org/):

```text
<тип>(<область>): <описание>
```

**Допустимые типы:** `feat` (новая функция), `fix` (исправление), `docs` (документация), `refactor` (рефакторинг), `test` (тесты), `chore` (рутина/настройка).

**Примеры:**
```bash
feat(api): добавить эндпоинт регистрации пользователя
fix(auth): корректная обработка отсутствующего токена
docs(readme): обновить шаги установки
```
*(Примечание: сами сообщения коммитов лучше писать на английском, это стандарт индустрии).*

## 🔀 Правила Pull Request (PR)

1. **Целевая ветка:** Всегда создавайте PR в ветку `dev`. **НИКОГДА** не делайте PR напрямую в `main`.
2. **Чеклист перед открытием PR:** Убедитесь, что:
   - [ ] Ваш код запускается локально без ошибок.
   - [ ] Вы добавили тесты для новой логики (если это применимо).
   - [ ] Ваша ветка синхронизирована с `dev` (локально решены все конфликты слияния).
3. **Автоматические проверки (CI/CD):** При создании PR GitHub автоматически запустит проверки. Если проверки провалятся (красный крестик ❌), код не будет рассмотрен, пока ошибки не будут исправлены.
4. **Описание:** Напишите краткое и понятное описание того, что делает ваш PR. Пример: *"Добавлена валидация ставок на аукционе и соответствующие модульные тесты"*.
